## P0 데이터 정확성

### 예산 상태의 반올림 오류

`BudgetPolicy.determineStatus()`는 반올림한 사용률로 임계값을 비교합니다. 예산 100, 비용 69.999이면 실제 사용률 69.999%가 70%가 되어 CAUTION으로 판정됩니다. 84.999와 99.999에도 같은 문제가 있습니다.

- 개선: 표시용 사용률과 판정을 분리합니다. 상태는 비용과 `예산 × 0.70 / 0.85 / 1.00`을 직접 비교합니다.
- 완료 기준: 69.999/70, 84.999/85, 99.999/100과 큰 금액·소수 예산 경계값 검증.

### 동시 수집 중복

조회 후 저장하는 구조는 순차 재수집을 처리합니다. V1 수집 조회 인덱스는 UNIQUE가 아니므로 두 요청이 동시에 기록이 없다고 판단하면 둘 다 INSERT할 수 있습니다.

- 개선: AWS 집계 기록에 적용할 고유 키 또는 전용 테이블을 설계합니다. 수동 비용은 같은 날짜·서비스에 여러 건 등록할 수 있어 전체 테이블에 단순 고유 제약을 추가하면 의미가 달라집니다.
- 완료 기준: MySQL 독립 트랜잭션 2개의 동시 수집에서 AWS 기록 1건 유지. 충돌·재시도·롤백 정책 검증.

### 사라진 항목과 음수 비용

현재는 응답에 나타난 항목만 갱신합니다. 재수집에서 기존 서비스가 사라지면 이전 금액을 유지할지 0으로 바꿀지 정의되지 않았습니다. 엔티티는 음수를 거부하므로 환불·크레딧 등 음수 항목이 있으면 수집이 실패할 수 있습니다.

- 개선: 기간 스냅샷 교체와 지원 비용 종류를 정의합니다. 통화 검증과 음수 금액 정책을 분리합니다.
- 완료 기준: 누락·0·음수·중간 저장 실패의 결과와 롤백을 실제 DB에서 검증.

## P1 실행 재현성과 외부 연동

### MySQL 및 Flyway 검증

H2 테스트는 `create-drop`, Flyway 비활성화 상태입니다. 엔티티 테스트 통과가 MySQL V1 SQL 검증을 의미하지 않습니다.

- 개선: Testcontainers MySQL로 빈 DB의 Flyway 실행, `ddl-auto=validate`, 소수 저장, CHECK·고유 제약 검증.
- 완료 기준: Java 17과 Docker가 있는 새 환경에서 재현하고 SQL·검증 결과를 함께 기록.

### AWS 호출과 저장 트랜잭션 분리

수집 서비스 전체의 `@Transactional`로 AWS 조회도 트랜잭션 범위에 포함됩니다. DB 연결을 즉시 점유한다고 단정할 수는 없지만 외부 호출과 저장 책임을 분리할 필요가 있습니다.

- 개선: AWS 조회·변환 후 별도 저장 Bean의 트랜잭션 메서드 호출. 제한된 재시도·타임아웃·외부 오류 응답과 수집 로그 정의.
- 완료 기준: AWS 실패 시 DB 변경 없음, 저장 중간 실패 시 전체 롤백, 일관된 HTTP 오류 응답.

### CI와 배포 검증 분리

최신 Actions의 테스트는 성공했지만 AWS 자격 증명 설정은 실패했습니다. PR용 테스트 워크플로가 없고 main 문서 변경도 배포를 실행합니다.

- 개선: PR 테스트 CI를 분리합니다. AWS 역할·신뢰 정책을 확인하고 문서 변경의 배포 정책을 정합니다.
- 완료 기준: PR CI 통과, 실제 ECR·SSM 성공 기록. 실패 시 기존 컨테이너 유지 또는 이전 이미지 복구 검증.
